# 调度台 · 设计说明

方向 C。三版里最像"工具"的一版：画廊是亮的，制作台是暗的，时间轴一直在下面。

## 三条原则

1. **舞台在前，控件在后。** 画面对角线占满中间，阶段、按钮、检查都退到边上。打开制作台先看见片子，不是先看见设置。
2. **阶段是承诺，不是菜单。** 六个阶段带编号和状态（已确认 / 待改 / 可选 / 未开始）。用户随时知道"现在在哪、还差什么"，而不是面对一排平级标签。
3. **检查要能被相信。** 每个数字都来自真实工具：`render(t)` 确定性、`window.READY`、抽帧尺寸、`readcheck`、`−14.1 LUFS`、`+0 帧`。没有假图表，也没有把"看起来不错"写成通过。

## 关键交互

- **画廊**：分类是带计数的文字索引，不是胶囊；搜索中/英/slug；海报 hover 只做 1.06 倍推近和细线边框，不做抬升阴影。
- **新建**：左侧风格 hero 常驻，右侧只问四件事；时长/语言/配音的改动实时汇总到底部一行；主按钮把用户直接送进制作台，并给导演第一条动作。
- **制作台**：左阶段、中舞台、右导演、底时间轴。风格帧是"主帧 + 三张 takes"的审片布局；重抽时按钮进入 1.6 秒的抽帧态，第 2 帧从"待改"变"可用"。渲染草稿有 0→100% 的排队态，完成后自动切到成片并新增版本行。
- **时间轴**：点击任意位置移动播放头并更新时间码；画面、字幕、音频三条轨。它不是装饰，是把"45 秒"变成可指的东西。
- **导演栏**：阶段切换时状态跟着变（正在看第 2 帧 / Treatment 已写 / 等你确认分镜）；快捷动作就是四句真的会发给 Agent 的话。

## 实现到 React 时

- 三个界面建议做成同一路由下的 `view` 状态（`gallery` / `new` / `desk`），别用三个页面，返回时保留滚动和筛选。
- 海报列表和 `styles.json` 由 Host 提供；66 张图不要一次解码，`loading="lazy"` + 4 列虚拟化足够。
- 制作台的四个区域用 CSS grid（`224px 1fr 342px` / `1fr 164px`），不要用绝对定位；Agent 收起时只改列宽。
- 风格帧的"主帧 + takes"需要一个 `takes[]` 数据结构（`{t, file, status, note}`），重抽是 Host job，轮询或 SSE 都行。
- 时间轴用 DOM 即可（12 张缩略图 + 三条轨 + 一条 playhead），不需要 canvas；点击换算 `clientX / width * duration`。
- 字体只用系统字体，避免插件里加载 webfont 的 FOUT；中文标题的宋体在 Windows 上会退到 SimSun，需要在 CSS 里补 `"Noto Serif SC"` 兜底。

## 1280 宽的风险

- 画廊从 4 列变 3 列，首屏只能看到 3 张海报；hero 右侧的"正在制作"会压到 330px，标题要允许换行。
- 制作台把左栏收到 198px、导演栏收到 310px；"风格帧"主帧约 620×349，takes 列仍能放下，但检查项的 4 列要变 2×2。
- 时间轴的 12 格缩略图在 1280 下每格约 70px，字幕块会更碎；建议 1280 以下只显示 8 格。
- 低于 980px 不作为目标：DSH 面板本身有最小宽度，届时导演栏改为抽屉，而不是继续压。

## 这一版最想被选中的理由

它把"看片"和"改片"放在同一个屏幕上：主帧、takes、检查、时间轴、导演，一眼能判断这一版能不能交。另外两版更擅长"选风格"的仪式感，这一版更擅长"做到一半"的掌控感。
